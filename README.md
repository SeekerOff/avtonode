# Установка ноды Remnawave

Один скрипт на новый сервер: нода нужной версии, страница-заглушка и
сертификат Let's Encrypt. Запускать на самой ноде, от root.

## Запуск

```sh
curl -fsSLO https://raw.githubusercontent.com/SeekerOff/avtonode/main/node-install.sh
bash node-install.sh
```

Через трубу (`curl ... | bash`) не запускать: скрипт задаёт вопросы, а труба
занимает стандартный ввод. Если хочется одной строкой — так ввод остаётся
за терминалом:

```sh
bash <(curl -fsSL https://raw.githubusercontent.com/SeekerOff/avtonode/main/node-install.sh)
```

## Что спросит

| Ответ | Переменная | По умолчанию |
|---|---|---|
| домен заглушки, он же `serverName` в Reality | `DOMAIN` | — |
| версия ноды (тег образа) | `NODE_TAG` | `2.8.0` |
| порт ноды для панели | `NODE_PORT` | `2222` |
| ключ из панели, строкой `SSL_CERT=...` или `SECRET_KEY=...` | `NODE_SECRET` | — |
| почта для Let's Encrypt | `LE_EMAIL` | без неё, писем об истечении не будет |
| адрес панели — для правила ufw | `PANEL_IP` | без него порт ноды не ограничивается |

Любой ответ можно задать заранее — тогда вопроса не будет:

```sh
DOMAIN=node2.example.org NODE_TAG=2.8.0 NODE_PORT=2222 \
PANEL_IP=1.2.3.4 LE_EMAIL=you@example.org NODE_SECRET='SSL_CERT=...' \
bash node-install.sh
```

**Версия ноды должна совпадать по мажору с панелью.** У `remnawave/node`
плавающих тегов мажора нет, поэтому версия указывается точно: панель 2.x —
нода 2.8.0, панель 3.x — 3.4.2 или новее. Тег проверяется на Docker Hub до
установки, при опечатке скрипт покажет список выпусков.

## Команды

```sh
bash node-install.sh          # установка или обновление
bash node-install.sh check    # только проверки, ничего не меняет
bash node-install.sh status   # что работает и до какого числа сертификат
```

Повторный запуск безопасен: прежние файлы сохраняются копиями с датой,
заглушка не перезаписывается. Сменить версию — `NODE_TAG=3.4.2 bash
node-install.sh`. Свою страницу — положить файлы в `/var/www/html`.

## Как устроено

`/opt/remnanode/docker-compose.yml` поднимает две службы в сети хоста:

- **нода** — слушает `NODE_PORT` для панели, ключ лежит в `.env` с правами
  600, логи в `/var/log/remnanode` с logrotate;
- **Caddy** — держит сертификат и отдаёт заглушку на `127.0.0.1:9443`,
  порт 443 не занимая. Его забирает Xray ноды под Reality и заворачивает
  туда всех, кто пришёл на домен без ключа — они видят настоящий сайт с
  настоящим сертификатом. Наружу этот порт не смотрит: слушается только
  localhost.

Сертификат берётся по проверке на порту 80, TLS-ALPN отключён явно — он
проверяет через 443, который нам не принадлежит. Сама проверка слушает
`127.0.0.1:8080`, а приходящее на 80 Caddy переправляет ей: проверочный
сервер он поднимает на интерфейсе того сайта, которому нужен сертификат, а
задать ему другой интерфейс в Caddyfile нельзя — только порт. Продлением
занимается сам Caddy, certbot и cron не нужны.

Порты заглушки и проверки можно сменить: `SITE_PORT` и `ACME_PORT`.

До того как панель выдаст ноде конфигурацию, HTTPS на домене не отвечает
вовсе — порт 443 ещё никто не слушает. Это нормально.

## Что вписать в панели

Нода: адрес сервера и `NODE_PORT`. В профиле конфигурации, inbound с
Reality: порт `443`, `serverNames` — домен заглушки, `dest` —
`127.0.0.1:9443`, `xver` — `1`.

Если прежние ноды ставились скриптами, где заглушка живёт в unix-сокете,
`dest` у них другой — `/dev/shm/nginx.sock`. Профиль конфигурации в панели
общий для назначенных на него нод, поэтому такой ноде нужен свой профиль.

## Проверки перед установкой

До записи любого файла скрипт сверяет: запуск от root, наличие docker
(поставит официальным установщиком, спросив), A-запись домена — с внешним
адресом сервера, существование тега на Docker Hub, свободны ли порты 80, 443
и порт ноды. При замечаниях отказывается; обойти — `FORCE=1`.
